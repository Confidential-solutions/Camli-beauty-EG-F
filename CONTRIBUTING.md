# 🤝 Contributing to Camli Beauty Egypt

Thank you for contributing to **Camli Beauty Egypt**! This guide outlines the development standards, Git workflows, and synchronization guidelines to ensure high code quality and smooth collaboration.

---

---

## 🌿 Git Workflow & Best Practices

- **Feature Branches**: Create focused branches for each feature or bug fix (`feature/`, `fix/`).
- **Keep `main` deployable**: Ensure all unit tests pass (`npm run test`) and code passes lint checks (`npm run lint`) before opening pull requests.
- **Conventional Commits**: Format commit messages according to the Conventional Commits specification.

## 🛠️ Local Development Setup

### 1. Prerequisites

- **Node.js**: `v20.x` or higher
- **Bun** (recommended) or **npm**

### 2. Getting the Code

```bash
git clone https://github.com/Confidential-solutions/Camli-beauty-EG-F.git
cd Camli-beauty-EG-F
bun install
```

### 3. Running Development Server

```bash
bun run dev
```

The app will start at `http://localhost:3000`.

## 🌿 Branching & Workflow

1. **Create a Feature Branch**:

   ```bash
   git checkout -b feature/your-feature-name
   # or for bug fixes:
   git checkout -b fix/issue-description
   ```

2. **Run Tests & Verify Changes**:

   ```bash
   bun run test
   bun run lint
   ```

3. **Format Code**:

   ```bash
   bun run format
   ```

4. **Commit Your Work**:
   Follow [Conventional Commits](https://www.conventionalcommits.org/):
   - `feat: add wishlist drawer component`
   - `fix: resolve RTL alignment on product card price tag`
   - `docs: update roadmap milestones`
   - `style: refine button hover transitions`
   - `refactor: optimize cart local storage sync`
   - `test: add routing tests for /best-sellers`

5. **Push and Open a Pull Request**:
   Push your feature branch and open a PR against `main`.

## 🎨 Styling & Component Guidelines

- **Tailwind CSS v4**: Use established design tokens from `src/styles.css`. Avoid inline arbitrary CSS rules unless necessary.
- **RTL/LTR Awareness**: Always verify new UI components in both Arabic (RTL) and English (LTR). Use logical spacing utilities (e.g., `start`, `end`, `ms-`, `me-`) when possible.
- **Accessible Overlays**: Any sheet, dialog, drawer, or popover must utilize the `panel-frame` utility and safe-area panel offsets to prevent clipping and stay within the viewport.
- **No Direct Edits to Route Tree**: `src/routeTree.gen.ts` is managed by TanStack Router. Do not edit this file manually.

---

## 🧪 Testing Guidelines

- Write tests in `src/test/` for new shared utilities, cart actions, or routing behaviors.
- Ensure all tests pass before opening a PR:
  ```bash
  bun run test
  ```
